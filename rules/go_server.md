# Правила сервера (server/)

Сервер делает то, чего клиент не может сам: сверяет личность, синхронизирует устройства
и ходит во внешние API, пряча ключи.

## Слои

```
internal/api      транспорт: роутинг, middleware, разбор запроса и сериализация ответа
internal/<домен>  логика: sync, library, srs, translate, ocr
internal/store    хранилище: SQL, никакой бизнес-логики
```

Правило одно и жёсткое: `api` не знает SQL, `store` не знает HTTP. Логика посередине
не импортирует `net/http`.

## Авторизация

- Токен выпускает Читавук, Wolfy его только проверяет тем же секретом.
- Свои эндпоинты выдачи токенов Wolfy не заводит: одна точка правды на два продукта.
- `user_id` берётся исключительно из проверенного токена, никогда из тела запроса.

## Данные

- Всё своё — в схеме `wolfy`. Таблицы Читавука доступны только на чтение.
- Каждая миграция — пара файлов `NNNN_имя.up.sql` / `.down.sql`, применяется по порядку.
- Запросы всегда с параметрами. Конкатенация SQL со значениями запрещена.

## Внешние API

- У каждого внешнего вызова есть таймаут и предел ретраев. Клиент не должен ждать
  дольше, чем ему обещано.
- Ответы DeepL и словарей кэшируются: один и тот же контекст не оплачивается дважды.
- На исчерпанный бюджет или недоступность провайдера отвечаем понятной ошибкой,
  а не пятисоткой.

## Стиль

- `golangci-lint run` и `go test -race ./...` зелёные до слияния.
- Ошибки оборачиваются с контекстом (`fmt.Errorf("...: %w", err)`).
- God-объекты запрещены: если структура зависит больше чем от пяти вещей, она делает
  больше одной работы.
