# Wolfy: памятка для агентов

Перед крупной правкой прочитайте `docs/architecture.md`; перед выпуском —
`docs/agents/deploy.md`. Эти два файла описывают границы системы и production,
а не заменяют чтение кода в затронутом модуле.

## Карта репозитория

- `core/`: Rust-ядро, парсинг EPUB/TXT/PDF, грамматика, SRS, библиотека,
  настройки и слияние. UI и сеть сюда не добавлять.
- `client/`: Compose Multiplatform для Android, Windows и Linux. Общую логику
  держать в `shared/commonMain`, платформенную — через `expect/actual`.
- `web/`: React/PWA; использует то же Rust-ядро через WASM и те же HTTP-контракты.
- `server/`: Go API, Postgres, синхронизация, файлы книг и внешние провайдеры.
- `client/assets/companions/notionists-v1/`: исходники и генератор runtime-пака.
- `tools/companions/`: нормализация и проверка ассетов компаньона.

## Инварианты

- Обычное чтение, разбор слова и локальные реплики работают без сети.
- Клиенты не содержат ключей ИИ/OCR/перевода; внешние запросы идут через сервер.
- ИИ получает текст книги как недоверенные данные, возвращает только проверенный
  JSON-контракт и имеет fallback по провайдерам. `response_format` включается
  возможностью endpoint, не именем модели. Резерв покрывает и провал контракта,
  а не только отказ транспорта: ответ верной формы с неверным содержимым даёт
  один ремонт у той же модели, затем следующую (`readingai.AskValidated`).
- Резерв дневного лимита возвращается по собственному контексту, а не по
  контексту запроса: отменённый читателем запрос уже отменил и его контекст,
  и квота осталась бы списанной за ответ, которого никто не увидел.
- «Исследования» удалены из продукта. Не возвращать их маршруты, таблицы или UI;
  актуальная персональная функция — компаньон.
- Файл книги синхронизируется отдельно от метаданных. Не считать наличие обложки
  или записи книги доказательством наличия файла на устройстве.
- Профиль компаньона синхронизируется; 100 локальных реплик имеют встроенный
  fallback. Обычные реакции не должны расходовать ИИ.
- Модель Beta-подсказок (`WOLFY_AI_MODEL`) не наследуется от модели OCR. Одной
  нужно зрение, другой нет, а цена отличается на порядок; наследование однажды
  уже увело весь текст разборов в дорогую модель для фотографий.
- Применённую миграцию не править. Журнал помнит имя файла, а не содержимое:
  правка не доедет туда, где миграция уже прошла, свежая база и CI останутся
  зелёными, а production молча уйдёт со старой схемой. Отменять и дополнять —
  только новой миграцией; отпечатки держит `store/migrations_test.go`.
- Путь к файлу книги на диске собирается из `book_files.storage_key`, а не из
  номера книги: номер меняется при схлопывании одинаковых книг, и файл обязан
  остаться доступным второму устройству.
- Память компаньона локальна для устройства: полный текст книги в неё не
  писать. Хранить только отпечатки кэша, короткие пересказы и ограниченную
  историю запросов; повтор из кэша не расходует Beta-квоту, память очищаема.
- Длительность анимации берётся только из `WolfyMotion` (`motion.paced`,
  `motion.settling`). Сырой `tween(300)` не знает про «уменьшить движение» и
  едет всегда; бесконечное движение под `motion.still` не заводится вовсе, а
  не анимируется из нуля в ноль. Стережёт `MotionDisciplineTest`.
- `Modifier.pressable` ставится до `clip`/`background`/`border`: сжатие это
  `graphicsLayer`, и фон, нарисованный раньше, в слой не попадает — сжимается
  одна подпись внутри неподвижной плашки.
- Свои экраны берут цвет только из `WolfyTheme`. Заимствованным компонентам
  Material (ползунок, переключатель, поле ввода, индикатор, подсказка) роли
  переводит `theme/MaterialBridge.kt`; отдельный `colors = ...` на месте вызова
  не заводить.
- `notionists-v1/runtime` не редактировать вручную: менять библиотеку/нормализатор,
  затем запускать `node tools/companions/normalize.mjs` и `validate.mjs`.
- Новое поле настроек обязано иметь default для старых файлов и одинаковое имя в
  Rust, Kotlin и TypeScript. Новая команда сессии добавляется в контрактный тест.
- Не логировать токены, ключи, текст книги и содержимое ответов ИИ.

## Проверки по области

```text
core:    cargo test --manifest-path core/Cargo.toml --locked
server:  cd server && go vet ./... && go test -p 1 ./...
web:     cd web && npm test && npm run build
assets:  node tools/companions/validate.mjs
client:  cd client && gradlew :shared:desktopTest :shared:compileKotlinDesktop
```

Для Android нужен JDK 17 и release-сборка в CI. Не коммитьте `.env`, keystore,
собранные пакеты и случайные пользовательские файлы. Не включайте чужие
незакоммиченные изменения в свой коммит.

Push в `master` запускает `.github/workflows/ci-deploy.yml`. Production считается
выпущенным только после зелёного workflow и успешного `/healthz`; красный CI не
обходить ручной выкладкой.
